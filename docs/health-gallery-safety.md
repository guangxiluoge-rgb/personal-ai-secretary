# 健康图片图库自动检索与防呆设计

## 目标

当用户进入健康资料入口时，客户端可以主动打开系统图库/照片选择器，帮助用户快速找到手环截图、体检报告、化验单、舌象或面部照片，并把用户确认的图片送入健康分析队列。

## 核心防呆规则

1. **永远不静默上传图库**：客户端只能主动打开系统 Photo Picker / Photos Picker；用户必须确认选中的图片。
2. **最小权限**：优先使用系统的“选择照片”能力，而不是申请整图库读权限。只有确实需要历史扫描时，才请求完整照片权限。
3. **本地优先筛选**：可在设备端使用文件名、EXIF 时间、OCR/视觉标签等非敏感索引做候选筛选；候选结果先展示给用户确认，再上传。
4. **健康图片识别候选**：手环/健康 App 截图常见关键词包括“心率、血氧、睡眠、步数、血压、体温、HR、SpO2、ECG、睡眠”等；医疗报告包括“检验、化验、体检、报告、血常规、肝功能、肾功能”等。关键词只用于候选排序，不直接认定图片属于某类医疗数据。
5. **重复防呆**：客户端计算 SHA-256；同一图片不要重复上传。服务端仍需再次校验。
6. **类型防呆**：支持 wearable / medical_report / tongue / face；未知类型统一进入 `unknown`，不得因为猜测而触发特定健康结论。
7. **异常防呆**：图片损坏、过大、格式不支持、OCR 为空时，允许用户重新选择，不进入分析。
8. **结果防呆**：AI 输出只作为健康管理/风险提示，不作为医疗诊断；`urgent` 只能触发平台后台告警和人工/专业复核流程。
9. **撤回**：用户取消选择时不产生健康记录；上传后的原图应按平台数据保留策略处理。

## 客户端行为

### Web/PWA

使用 `<input type="file" accept="image/*" multiple>` 或平台支持的 Photo Picker。浏览器不允许网页无提示地读取用户整个图库，因此“自动进入图库”只能表现为进入系统选择器，而不是静默扫描。

### iOS

优先使用 PHPickerViewController / PhotosPicker，让系统负责授权和选图；仅在明确产品需求下申请完整 Photos Library 权限。

### Android

优先使用 Android Photo Picker（`PickVisualMedia` / `PickMultipleVisualMedia`）；只有需要持续读取图库历史内容时才申请 READ_MEDIA_IMAGES 等权限。

## 上传协议建议

客户端提交：

- `image_type`: wearable | medical_report | tongue | face | unknown
- `client_sha256`: 图片 SHA-256
- `source`: gallery | camera | file
- `selection_confidence`: 客户端候选排序置信度，仅用于排序，不能作为医疗结论

服务端重新计算文件哈希并校验 MIME、大小和用户权限，然后创建 `HealthAnalysisJob`。

## 用户体验

入口按钮建议显示：

> **从图库找健康图片**
>
> 自动帮你优先找可能的手环截图、体检报告和健康记录；你确认后才会上传。

如果用户一次选择多张图片，客户端先按类型分组，再让用户一次确认。不要把“系统识别为医疗报告”直接写成确定结论。
